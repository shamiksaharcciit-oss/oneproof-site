The latest first. onetrace's full list of changes is in the changelog inside its source distribution.

onetrace 0.8.02026-11-13 · with onetrace-verify 0.8.0 and onetrace-auto 0.8.0, and onetrace-explain 0.3.1

Record format 0.5: a step's store state, its kind and agent, messages between agents, and the link between services.

Store state

Inside a step, ot.state.read and ot.state.write each add an entry to the receipt: the store, its kind, the key's digest, the version the store reported (not observed where none is given, never made up) and a digest of the data. onetrace-auto records a LangGraph checkpointer, psycopg, chromadb, pinecone, S3, Google Cloud Storage, Azure Blob, Iceberg and Delta; pinecone, Google Cloud Storage and Azure are tested against fakes with their public shape.

Expectations checked during the run

With expect_mode="record", each expectation is read as its step returns and its result is recorded with it. With "stop", one that reads FAIL stops the run after the failing step's receipt is written. off, the default, writes nothing. A stop never guards the step that failed, and an expectation that holds does not show the output was right.

The cross-service link

A step can send onetrace-parent to another service (ot.outgoing_headers(), or onetrace-auto to the hosts on ONETRACE_PROPAGATE), and the callee's run records the caller's run, step and chain head, and the origin: the run where the whole request started. ot.wsgi and ot.asgi run each request in a run of its own, and onetrace diff --linked-run follows the link.

Also in 0.8.0

Record format 0.5: every receipt is stage-receipt/0.5, and its new members are optional. onetrace-verify 0.6.1, 0.7.0, 0.7.1 and 0.8.0 read the golden example and both quickstart runs written at 0.5: exit 0, no FAIL row. After the rows of a run holding the new members, onetrace-verify prints what they do not show, and adds it to --json's non_claims.

What kind of step this is, and which agent ran it: @ot.stage(kind=...) takes one of eight kinds (model call, tool call, retrieval, decision, state read, state write, transform, other). With none given, the receipt says nothing ("kind not recorded"), never other. A tool call step writes its tool-call record. @ot.run(agent=...) names the run's agent, and a step's own agent is written where it differs.

Messages between agents: ctx.message(to, kind, body) records a message a step sent, by its digest (its bytes kept where the run keeps outputs), and ctx.received(ref) records what a step took in. A message is not an output: it changes no verdict.

A re-run with parts chosen separately: onetrace reproduce RUN --config-of REF --only answer.model takes only the parts named from REF's kept configuration; every other part stays RUN's. With record_code=True a run records its commit, and --code-of B re-runs the code at the commit run B recorded, in a temporary worktree, with today's environment. You are told what comes from where before it runs. It shows the combination today, with today's services and model: code from B with today's environment is not B's run.

The recipient confirmation: ot.permit_presented(token, request=...) and ot.confirmation(token) record the permit a step presented, read without checking its signature, and the recipient's confirmation, its token kept beside the run. onetrace-verify --recipients FILE reads five confirmation rows. A confirmation is the recipient's word, signed, for an effect or a refusal.

The writer: receipts are queued and written in batches, with a journal in the run's folder. When a decorated or auto-recorded run starts, a killed run in the same runs folder is recovered up to its last confirmed receipt, and its close says it was recovered; onetrace recover RUN does the same by hand.

onetrace-explain 0.3.1 releases with onetrace 0.8.0. Its pin admits onetrace 0.8 (onetrace>=0.6.1,<0.9), and a reply withheld for holding the key is said "not kept" once.

Upgrading: the record format moves to 0.5. onetrace-console 0.7.0 pins the onetrace release it runs on, onetrace 0.7.1: with onetrace 0.8.0, give the console an environment of its own until a console release supports it.

Known gaps: concurrent and multi-writer runs, and chunked tree digests for large outputs, are not in 0.8. onetrace-run --per request is refused: a run per request comes from ONETRACE_AUTO_PER=request, under Starlette and Flask. model_usage.cost is specified and not written.

onetrace 0.7 runs, and zero-config runs

The console reads record format 0.4 beside the earlier formats, and runs on onetrace 0.7.1. A run onetrace-auto recorded shows the libraries it hooked, what it could see, and each gap.

Whether a run closed, and how it ended

A Closed column in the runs list, in the verifier's own words: "closed: by exit", or "not closed: the record ends at" its last step. A run's page lists each step's expectations and whether they held.

Set up Explain in the console

A form for the provider, model and key, the key kept in your system's keychain with onetrace-explain 0.3. The page says who can read it, and the console stores no key.

Also in 0.7.0

One environment: pip install onetrace onetrace-console onetrace-explain onetrace-auto installs together, and pip check finds nothing to report.

The first-run-to-leave page says its answer first, in one sentence from the records, then how to read it in plain words. Each gap gives its reason, and one "Find the first run to leave after" control replaces a link on every row.

The app's spans at a differing step, attribute by attribute: baseline and candidate side by side, the rows that differ first.

Expectations declared after the run: on a local console, check a run against an expectations file, shown apart from the run's own.

A tokenizer from this machine shows a model step's tokens as text, kept only where its digest matches the record's.

The same release files on Windows as on Linux, byte for byte.

Smaller: the Compare picker keeps each label with its select; a static export shows Compare disabled ("Needs a running console."); start-up progress reads cleanly in Windows PowerShell 5.1; a sub-agent's run link isn't read as a step's input; CSRF values are compared in constant time; the sign-in limit counts a rolling window.

Known gaps: a run killed while it records keeps onetrace's .lock, so it reaches a console only by upload. There is no identity provider: a signed-in person is always a viewer. Lint, format and type checks are not part of the release gate yet.

onetrace 0.7.1with onetrace-verify 0.7.1 and onetrace-auto 0.7.1

A patch: Ctrl-Break on Windows, and a first difference headed as one.

  • onetrace-run on Windows waits through a Ctrl-Break, as it does at a Ctrl-C, and exits with the command's status.
  • onetrace localize heads its text report's block FIRST DIFFERENCE at. Its fields and the JSON report's keys are unchanged.
  • localize's help line reads "one run: first unclean stage; two runs: first difference and where it starts".
  • The record format is unchanged at 0.4: a 0.7.0 verifier reads a 0.7.1 run as it reads a 0.7.0 run.

onetrace 0.7.0with onetrace-verify 0.7.0 and onetrace-auto 0.7.0

Every run says whether it finished, and a library call can record itself.

A close receipt

Every run ends with one, so a finished run and one cut short read differently.

Zero-config recording

onetrace-run records calls through httpx, requests and openai, with no code change.

Re-runs stop before a recorded write

onetrace reproduce stops before a step recorded as write or unknown; --allow-writes runs it.

Also in 0.7.0

onetrace check checks one claim about a run or a pair of runs, and records the check as a run of its own.

A twin and a counterfactual: re-run with another run's configuration, or put one step's output in from another run. A counterfactual does not show that the step made a difference.

Step expectations declared in code and recorded with the run. One that holds shows the rule held, not that the output was right.

Self-hosted vLLM capture at L1, L2 and L3 writes the model-call record 1.1. L3 has not been run on a GPU.

Upgrading: the record format moves to 0.4. onetrace-console 0.5.1 and 0.6.0 pin onetrace 0.6.1, so install 0.7.0 in an environment of its own until a console release runs on it.
