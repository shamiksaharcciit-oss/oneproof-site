What's new onetrace 0.4.0

Send a run to your tracing tools. Compare many runs at once.

onetrace 0.4.0 and onetrace-verify 0.4.0 are on PyPI, with a new, separate package: onetrace-explain 0.1.0. This page also covers 0.3.0 and 0.3.1, which shipped without a page of their own. The record stays what it was: one receipt per step, checked by a verifier that doesn't trust your code.

In 0.4.0

Three new ways to read your runs.

Each one is a view of the record. None of them changes a verdict.

Send a run to your tracing tools

onetrace export otel RUN writes a run as one OpenTelemetry trace in OTLP/JSON: a span per step, linked where one step read another's output. The same run exports the same bytes. It makes no network calls and needs no OpenTelemetry package, and values, exception text and paths are never exported. The trace is a view; the record stays the evidence.

Many runs, side by side

onetrace drift compares a series of runs, each with the first run or with the one before, and every comparison is a diff of its own. Add --durations to see each step's time from its receipts, with a note on the steps that got slower. Timing is shown, never judged.

A suggested explanation, checked

onetrace-explain asks a model you configure where to look in a comparison, then checks every claim against the record. Claims that cite nothing, misquote the record or claim to know why something differs are dropped. Everything it shows is labelled AI-generated and may be wrong. More below.

pip install --upgrade onetrace
onetrace export otel runs/<run> --out trace.json
onetrace drift runs/run-1 runs/run-2 runs/run-3 --against first --durations

Also in 0.4.0

Records that say more, and pipelines that run in parallel.

Record format 0.3

A stage can be declared optional, and a run that skips it still reads complete. A step a plan held back before it ran keeps the link it attempted. A run can declare that it keeps no output files. An earlier verifier reads each of these the same way or more strictly, never more loosely.

Concurrent stages, named

ot.map (threads) and ot.gather (asyncio) run a stage over many items and name each call by its item, never by the order calls finished in. ot.pool and ot.carry carry the run into threads you start yourself.

Inside your framework

onetrace.langchain records messages and prompt values without their per-call ids. onetrace.langgraph records which node wrote each key of a graph's state, so a comparison can follow a value back to the node that wrote it.

onetrace-explain 0.1.0

A suggestion about a record, never a reading of it.

A separate package. onetrace, onetrace-verify and the console neither depend on it nor import it, and nothing they report changes with it.

You choose what's sent

It sends a fixed evidence packet to the model you configure: an OpenAI-compatible endpoint or the Anthropic Messages API. Your machine's paths, your environment and the model key are never in it. Kept text goes only with --include-text, and --dry-run shows the exact packet first.

Claims are checked before you see them

Every claim has to cite the record and quote it correctly. Claims that don't are dropped, without asking any model, and so is any claim to know why something differs. What it suggests next is a onetrace command you can run.

It leaves a record too

Each explanation is recorded as a onetrace run of its own, so you can check later what was sent and what came back.

pip install onetrace-explain
onetrace localize runs/A runs/B --out report
onetrace-explain report --dry-run

In 0.3.1

Fewer false alarms, and comparisons that fit a pull request.

Follow the output you care about

onetrace localize A B --for <stage> starts from one output and walks back to where its change began.

Name the noise you expect

--mask FILE on diff and localize sets aside the differences you expect between releases, and every step a mask changes says so. onetrace mask suggest A B drafts a mask from two runs.

A summary for your pull request

onetrace summary prints a short Markdown summary of a comparison, and of the verifier's result, for a pull request comment. onetrace match finds the earlier runs that were called with the same inputs.

In 0.3.0

Gates for your CI.

onetrace-verify 0.3.0 added three opt-in gates. --require-signature fails a run with no valid signature. --require-trusted fails one not signed by a key you trust. --require-complete fails one whose declared stages didn't all run. The onetrace GitHub Action runs the verifier and the comparison on every pull request, and posts the summary there.

Upgrading

One command, and your old runs still verify.

pip install --upgrade onetrace

onetrace-verify 0.4.0 comes with it and reads every earlier record. The console, onetrace-console 0.2.1, runs on onetrace 0.3.0: installed into the same environment, it keeps onetrace at 0.3.0. To try 0.4.0's new commands now, use an environment of their own. A console for 0.4.0 is on its way.

The full list of changes is in the manual and in each package's changelog.
