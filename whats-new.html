onetrace-console 0.6.0on onetrace 0.6.1

What kind of difference, when a pipeline left its reference, and your app's own traces.

The kind of first difference

One line at the first difference says what kind of thing differs there: the step's inputs, a model call on equal inputs, a decision, or an output that was not kept.

The first run to leave the reference

A pipeline's runs in recorded order, each read against its reference, and the first run that departs, by step or after a time.

Your app's spans

Give the console your app's OpenTelemetry export, as OTLP/JSON, and a step shows the spans it ran, joined by the trace context onetrace recorded.

Also in 0.6.0

A JSON output's members that differ, by path, each number as written, never a float.

The app's spans at the first difference, ranked, as facts from the app's traces. No verdict changes.

A run's configuration against its pipeline's reference run, step by step. An item a record lacks reads "not recorded", never "same".

A model step's token as text, on a local console, only where the tokenizer files you name hash to the record's digest. A public console decodes nothing.

The demo's app traces, labelled as example data.

Known issue: just after Explain is pressed, the page that follows its progress can show an error naming the explanations folder once; reloading it reads correctly. A fix is planned for 0.6.1. The console reads records up to format 0.3, so runs from onetrace 0.7 are not read yet.

pip install --upgrade onetrace-console

onetrace 0.7.0with onetrace-verify 0.7.0 and onetrace-auto 0.7.0

Every run says whether it finished, and a library call can record itself.

A close receipt

Every run ends with one, so a finished run and one cut short read differently.

Zero-config recording

onetrace-run records calls through httpx, requests and openai, with no code change.

Re-runs stop before a recorded write

onetrace reproduce stops before a step recorded as write or unknown; --allow-writes runs it.

Also in 0.7.0

onetrace check checks one claim about a run or a pair of runs, and records the check as a run of its own.

A twin and a counterfactual: re-run with another run's configuration, or put one step's output in from another run. A counterfactual does not show that the step made a difference.

Step expectations declared in code and recorded with the run. One that holds shows the rule held, not that the output was right.

Self-hosted vLLM capture at L1, L2 and L3 writes the model-call record 1.1. L3 has not been run on a GPU.

Upgrading: the record format moves to 0.4. onetrace-console 0.5.1 and 0.6.0 pin onetrace 0.6.1, so install 0.7.0 in an environment of its own until a console release runs on it.

Install
pip install -U "onetrace[crypto]"
pip install onetrace-auto
onetrace-console 0.5.1on onetrace 0.6.1

Read a console store from your own program.

  • store_read answers which runs share a configuration, which name the same model files, and a run's neighbours.
  • Each model-call record is linked from its run's page.
  • An earlier comparison points to the newer one of the same two runs.
onetrace-explain 0.2.0

Give it two runs: what changed, the evidence, and checks you can run.

  • What changed and the evidence come with no model and no network calls.
  • A model's reading is optional, labelled AI-generated, and each claim must cite the record.
  • Checks are marked "runnable here" or "needs a runner you name", and never run for you.
