How it works

Small records, one chain, an independent check.

Every claim the product makes rests on four parts. Each has a narrow meaning, and the format is published.

out: sha256:7c0…
answer
prev: sha256:e8d…

MANIFEST.json

Digests shortened and illustrative.

1

The receipt

Each step writes one receipt in canonical JSON: its inputs and outputs by digest, the tool and its settings, and how it ended. The same content always gives the same bytes.

2

The chain

Each receipt names the digest of the one before. The manifest ends in a chain head. Change, remove or reorder a receipt and the links stop matching. Since onetrace 0.7 every run ends with a close receipt, so a finished run and one cut short read differently.

3

The verifier

onetrace-verify reads bytes alone, with the Python standard library and no network. It checks canonical form, every link, and with --require-artifacts every output file. Each check prints PASS, FAIL or NOT-RUN.

4

The verdicts

A comparison gives each step one verdict about its output: same, FIRST DIFFERENCE, downstream, reconverged, or COULD NOT CHECK, which is never read as a pass.

Signatures and anchors

Signature: an Ed25519 signature over the chain head, by a key you hold. It shows the key's holder signed, not who the holder is.

Anchor: a timestamp proof from an outside party. It shows the record existed by a time, not when the run happened.

Both sit beside the record and change none of its bytes.

The limits

What it does not establish.

Not a truth oracle

A faithfully recorded wrong answer verifies. A record says where bytes came from, not whether they're right.

Not proof against a writer

Someone who can rewrite storage and every digest isn't stopped by verification alone. Keep the chain head elsewhere, or anchor it.

Not bit-exact everywhere

Reproduction isn't claimed across machines for numeric steps. Unseeded model calls read could not check, with the originals kept.

The format is published.

It is written up as an Internet-Draft so other programs can read a record. Every record carries its format version, and a verifier refuses a version it doesn't implement.
